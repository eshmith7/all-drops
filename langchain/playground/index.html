A chain follows a script. An agent decides.

A chain runs the steps you wrote, in the order you wrote them. An agent loop runs until the model stops asking for things. Same question, same model — press play and count the steps.

An agent
from langchain.agents import create_agent

agent = create_agent(model=M, tools=T, system_prompt=S)
agent.invoke({"messages": [{"role": "user", "content": q}]})
0press play
Same model, same question. One of them has somewhere to go and look.
DEFINITION

Chain

A fixed pipeline you compose yourself — prompt | model | parser. Still current, still the right call when you already know every step.

DEFINITION

Agent loop

Call the model → run whatever tools it asked for → feed the results back → ask again. It ends when the model returns no tool calls.

DEFINITION
create_agent

      
The one constructor in LangChain v1, from langchain.agents. It returns a compiled graph, so you get .invoke(), .stream() and .astream() with no wrapper around it.

    
DEFINITION
system_prompt

      
Your standing instructions, as a plain string. It becomes the SystemMessage at the head of every turn. Not prompt= — that keyword does not exist.

Your docstring is a prompt. It's read on every single turn, by a model choosing between three tools — and it is the only thing standing between a clean call and a guess.

  

  

    
DEFINITION
@tool

      
The decorator from langchain.tools that turns a plain function into something a model can call. It reads the name, docstring and type hints and builds the schema from them.

    
DEFINITION
Tool description

      
The text the model chooses by. It defaults to your docstring; override it with description= or an Annotated[str, "..."] argument when the docstring has other jobs.

DEFINITION
Messages

      
SystemMessage, HumanMessage, AIMessage, ToolMessage — all from langchain.messages. The whole conversation, tool traffic included.

    
DEFINITION
State

      
The dict flowing through the graph. For a default agent it is just {"messages": [...]} — the same shape going in as coming out, which is why you can append to it and re-invoke.

Memory is a thread_id.

  
An agent forgets everything between calls unless you hand it a checkpointer. After that, a thread_id decides which conversation you're continuing — or whether you're a stranger.

Old tutorials will tell you to attach ConversationBufferMemory. It's deprecated and lives in langchain-classic now. Memory stopped being an object you hand the chain and became state the runtime saves, keyed by a thread.

  

  

    
DEFINITION
Checkpointer

      
The thing that saves state after every step. InMemorySaver for a notebook; swap in SqliteSaver or PostgresSaver when it has to survive a restart.

    
DEFINITION
thread_id

      
The conversation's name, passed in config rather than in the message. Same id, same history. New id, clean slate.

  







  
06

  
The five things tutorials still get wrong.

  
LangChain 1.0 landed in October 2025 and most blog posts predate it. Five APIs you'll still be handed, and what replaced each. Most of the old ones survive in langchain-classic — while LCEL is the one thing here that never went anywhere.

  

    Check your code
    

    

    
One rule for reading any LangChain tutorial: if it imports from langchain.chains or langchain.memory, it predates 1.0. The modern surface is small — create_agent, @tool, messages, a checkpointer.

  

  

    
DEFINITION
langchain-classic

      
The separate package the pre-1.0 surface retired into. pip install langchain-classic keeps old code running — it is a migration crutch, not somewhere to start.

    
DEFINITION
LCEL

      
The pipe syntax — prompt | model | parser. Not deprecated, not going anywhere. What changed is that it is no longer how you build agents.
